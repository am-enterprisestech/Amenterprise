## Key decisions & rationale

1. **About page goes static** — the current page pulls from `about_blocks` DB table which may be empty in any environment. The story content (2018–2025 timeline, office count, team size) is factual and fixed; hardcoding it guarantees the page always renders meaningfully.

2. **Directors are filtered from `team_members` via `is_director` column** — a separate `directors` table was considered but rejected. `team_members` already has all needed columns (`role_title`, `bio`, `long_bio`, `photo_url`, `slug`, etc.) and an existing public-read policy. Adding a boolean flag is the minimal schema change; it avoids duplication and lets a director link to their full `/team/$slug` profile page.

3. **Migration file is `0010_directors.sql`** — the highest existing migration is `0009_project_portal_premium.sql`. Using `0010` follows the existing sequential naming convention.

4. **`useLiveList` client-side filter for directors** — rather than adding server-side filter support to `useLiveList` (which could have unknown effects on other call sites), filter `rows` client-side. The team list is small (15–17 people); this is not a performance concern.

5. **Navbar uses plain hover/state logic, not `NavigationMenu` radix primitive** — the existing Header already implements a complete, working hover-dropdown system with accessibility attributes. Swapping it to `NavigationMenu` would require a large rewrite with no user-visible benefit. The change is purely structural (updating `baseNav` items).

6. **No FAQ route fix needed** — `/faq` is referenced in the footer and current navbar but was not in the required navbar spec; it's not listed as broken. The existing `src/routes/faq.tsx` (if present) is left untouched.
